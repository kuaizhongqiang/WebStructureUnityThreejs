## D Web / Three.js 线

### Q-R2-D1 先解释上一轮的 Q-D2，再请你确认【P0】

上一轮你选了 Q-D1 的"按建议来"（Vite + TypeScript + Vue 3 + **裸 three**），但 Q-D2（"UI 用框架、三维用裸 three"的混合）你写"不太懂，需要解释"。这里说清楚：

**两种写法的区别**

| | 声明式封装（R3F / TresJS） | **裸 three（我们的选择）** |
|---|---|---|
| 怎么写场景 | 用组件/模板描述：`<mesh><box-geometry/></mesh>` | 直接写代码：`scene.add(new THREE.Mesh(...))` |
| 谁驱动场景 | 框架把场景对象接到响应式系统上，数据变了自动重建/更新 | **我们自己**在 `requestAnimationFrame` 里渲染 |
| 适合什么 | 页面上有**很多个**小三维卡片，每个卡片状态由 UI 数据驱动 | **一个大画布** + 若干交互件（我们的教学场景） |

**为什么选裸 three**
1. **性能**：三维对象每帧都在变（相机、物体显隐、旋钮角度）。把这些对象塞进响应式系统，等于给每帧都增加一层代理与依赖追踪，收益却几乎为零。
2. **可排查**：出问题时能直接照 three 官方文档与示例排查，不用先穿过一层封装。
3. **生命周期清晰**：一个教学任务页 → 一个 `Viewer` → 离开时 `dispose()` 一次。声明式封装里"什么时候真的销毁了 GPU 资源"往往要靠框架保证。
4. **与 Unity 侧心智一致**：两边都是"我们自己持有场景与渲染循环，Web 外壳只下指令"（DEC-08）。

**"UI 用框架"指什么**：页面、导航、题目、表单、状态条这些用 Vue 组件写（DOM 层，DEC-16），**不是**用 Vue 去描述三维内容。

**已经在代码里体现**：`web/src/viewer/Viewer.ts`（裸 three 封装）+ `web/src/pages/TaskView.vue`（Vue 管页面，`onMounted` 挂载、`onBeforeUnmount` 释放）。

- 选项：A) **确认，保持现状** B) 改用声明式封装（R3F / TresJS），我重写三维层 C) 还是不清楚（我再换一种说法 / 直接在代码里给你对照）
- ★建议：**A**。
- 回答：A
