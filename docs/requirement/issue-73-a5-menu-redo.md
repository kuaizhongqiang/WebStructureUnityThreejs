## 3 并列原则与筛除线（本轮中心原则）

> **目录页是并列展示。** 九个项目之间没有先后、没有依赖、没有强弱；"站数 / 下一站"只是每个项目**自己**的属性，不是项目之间的关系。 —— 负责人 2026-10-16

### 3.1 筛除线（不满足直接出局）

| # | 出局形态 | 为什么出局 |
|---|---|---|
| S1 | "先 → 后"的**推进箭头**（流水线 / 时间带 / 看板） | 把并列改成了有向推进 |
| S2 | "谁连谁"的**连线**（接线图 / 电路板 / 节点散射的**边**） | 连线即声明项目之间的依赖或因果 |
| S3 | "谁更重要 / 更多"的**排位**（排行榜 / 大小分档 / 远近分档） | 位置或尺寸一旦编码权重，就产生了强弱 |
| S4 | "必须按顺序走完"的**强约束**（关卡 / 解锁链 / 逐级开放） | 给用户强加顺序，且与"游客可任意进入"冲突 |

⚠️ **S2 的边界要写清楚**（这是最容易误伤的一条）：筛除的是**项目与项目之间的边**。"用户当前在看哪一格 / 光斑落在哪一格"是**观看关系**，不是内容关系，不在筛除线内；站点线（A5-R6 要求对齐的那套视觉语言）画的是**同一个项目内部**的站与站，也不在筛除线内。

**留在场上的只能是：并列关系不变，动的是呈现与反馈。**

### 4.0 横向对照表

| | ① 伪三维卡片滚动 | ② 节点散射 | ③ 六边形蜂窝 | ⑦ 档案抽屉 | ⑧ 探照灯取景器 |

| **键盘** | ←/→ 或 Tab 移焦点；**需自实现焦点跟随** | 二维自由度 ⇒ 方向键无自然语义，只能退化成"按编号下一个" | 蜂窝天然六邻接，只有四方向键 ⇒ **需砍成四邻接** | Tab 顺序 = 格子顺序，Enter 开合，焦点环画在格子上 | **方向键在网格上移动光斑，天然二维邻接，键盘比鼠标更顺手**（五者唯一） |

### 4.1 候选 ① 伪三维卡片滚动（垂直 / 水平）— 负责人提出

- **机制**：卡片沿一条轴排开，近大远小 + 透视纵深，滚动或拖拽在轴上移动，居中者获得焦点。
- **并列语义（为什么过筛除线）**：位置本身不表示关系，仅表示"当前看哪一张"。
- **动感来源**：滚动位移 + 景深缩放。
- **鼠标**：滚轮 / 拖拽换焦点，悬停微抬，点击进入。
- **键盘**：←/→ 或 Tab 移焦点；**需自己实现焦点跟随**（规则 §5 的焦点环只在键盘模态画）。
- **窄屏**：透视缩到最小，退化成单列一屏一张。
- **实现要点**：`transform: perspective() translateZ()` + scroll 监听；纯 DOM，不引 3D 库。
- **已知冲突与已定处理**：与"响应 / 滚动限制"冲突 → 负责人裁定 **可考虑异步加载绕过响应限制**。
- **遗留风险（未定，须写进评审）**：规则 §10 的全局 `prefers-reduced-motion` 会把位移压到 0.01ms（`components.css:913-919`）⇒ 该档下"伪三维"变成**瞬切**，需另定**静态降级形态**。规则 §10 明确"**不要再各自写媒体查询**"（`design/07-frame-style-rules.md:133-135`），所以做法必须是**在同一份媒体查询下换布局**，不是加时长。

### 4.2 候选 ② 节点散射 — 负责人提出

- **机制**：项目作为节点散在平面上，位置本身带信息，缩放 / 平移聚焦。
- **动感来源**：节点浮沉 / 呼吸 + 连线生长 + 视图平移缩放。
- **鼠标**：平移画布、滚轮缩放、悬停放大节点。
- **键盘**：散点是二维自由度，方向键无自然语义 ⇒ 只能退化成"按编号顺序下一个"。
- **窄屏**：散点在窄屏几乎必然重叠，退化成列表。
- **实现要点**：坐标手工或按规则算好写死（**不引物理引擎**）。
- **已知冲突与已定处理**：位置算法 / 图表达 → 负责人裁定 **"graph 表达有很多案例，位置具体算法可以找参考"** —— 即**不作为阻塞项**，实施时找现成参考。本文只需把"**位置编码什么**"列为**待定**（编号 / 类别 / 还是随机撒）→ §6 待拍板 6。
- **🔴 语义风险（本文必须点明）**：按 §3.1 S2，**节点之间的"边"会把并列读成有向**。而"连线生长"正是这个方案的动感来源之一 ⇒ 这两条直接冲突，是五个方案里**唯一自带语义冲突**的一个。**建议**：要么去掉边、只留节点浮沉（那时"散射"的必要性下降，接近 ⑧ 的平面排布），要么把边限定为装饰（等权重、无方向、不随进度变化）。

### 4.3 候选 ③ 六边形蜂窝 — 负责人提出

- **机制**：正六边形平铺，邻接关系 = 平级并列，靠格位导航。
- **动感来源**：格位高亮流动 + 进入时六边形展开。
- **鼠标**：悬停抬起、点击进入。
- **键盘**：蜂窝天然六邻接，但只有四个方向键 ⇒ **需砍成四邻接**。
- **窄屏**：格子变小、正文不可读 ⇒ 必然退化成分页 / 列表。
- **实现要点**：`clip-path: polygon()` 或 SVG；六边形内接文字长行会溢出，**需限行数**。
- **已知冲突与已定处理**：与规则 §2 的"圆角只有 6 级、**禁止游离字面值**"（`design/07-frame-style-rules.md:22-35`，刻度值见 `tokens.css:98-103`：4 / 8 / 12 / 16 / 20 / 28）冲突 → 负责人裁定 **"新建样式"**。
  ⇒ 本文据此明写为 **"建立新样式例外"**，供评审确认：不走既有圆角刻度，另立一档并说明。**边界**（只限本页 / 升级为设计系统一档）未定 → §6 待拍板 7。

### 4.4 候选 ⑦ 档案抽屉 — 本文提出，负责人已认可为**备选**

- **机制**：界面 = 一叠**等厚**的抽屉 / 档案夹，统一方向、统一厚度码放；抽屉"名称"朝外，内容藏在里面。拉开哪一格，哪一格从板子里滑出来、露出内页（站点数、下一站、简介）。
- **并列语义**：抽屉盒里每格**厚度相同、地位相同、谁也不指向谁**；"打开"是**用户的动作**，不是内容的关系。
- **动感来源**：抽屉滑出 / 收回 + 其余格子轻微挤压让位（**只让位，不位移**，避免读成顺序）。
- **鼠标**：悬停格子微微探出（可读名称），点击滑到底露出内页，再点收回。
- **键盘**：Tab 顺序 = 格子顺序；Enter 开合；焦点环画在格子上。
- **窄屏**：抽屉变竖排手风琴，一屏两三格，语义不变。
- **实现要点**：纯 CSS `translate` / `flex-basis` 过渡；拉开态一个 `:has()`／class 即可，**不需 JS 布局计算**。
- **遗留（未定）**：
  1. 静止时**可能退化成现在的网格** —— 成立与否全看"拉开"那一下的手感；
  2. "抽屉头"的视觉规则（等厚平行边）与规则 §2 的圆角刻度**只有 `--radius-xl` 一档**（20px）对应得上，**需要定档**（沿用 `--radius-xl`，还是同 ③ 走"新建样式"）。

### 4.5 候选 ⑧ 探照灯取景器 — 本文提出，负责人已认可为**备选**

- **机制**：九个项目在**同一张平面**上等大等距铺开（等同现在网格的排布，**不倾斜、不纵深**）；平面上只有一团**用户控制的光斑**：光斑内清晰且带上视觉主体，光斑外整体压暗、去色。光斑位置由鼠标 / 触控 / 方向键移动，**点击 = 进入光斑中心那一个**。
- **并列语义**：排布**完全没有结构**（等大等距的并列位），**唯一的结构是"你正看着哪一块"** —— 观看关系，不是内容关系（正对 §3.1 S2 的边界）。
- **动感来源**：光斑移动的明暗过渡 + 被照亮那格的轻微抬起；停住时一圈**很慢**的呼吸。
- **鼠标**：移动即移动光斑（**无需精确悬停** ⇒ 回避命中区问题，见 §5），点击进入。
- **键盘**：方向键在网格上移动光斑，**天然二维邻接**；**键盘比鼠标更顺手**（五个候选里唯一如此）。
- **窄屏**：光斑保留，网格缩成两列；触控改成"点哪块亮哪块"。
- **实现要点**：一层 `mask`／径向渐变做光斑，**格子本身不动** ⇒ **"减少动态效果"档下退化成本最低**（光斑瞬移，布局逻辑不崩）。
- **可延展（后续可能，不在本次范围）**：`web/src/viewer/` 已有产品自持三维舞台（DEC-98，`DECISIONS.md:838`），"光斑内是活的"可**后续**升级成光斑内跑实时预览，**不改本页骨架**。

### 并行安全判定

| 工作项 | ① 写入范围与其它项互斥？ | ② 共享契约已冻结？ | ③ 验收可机械判定？ | 结论 |

逐项依据（按 doc-write 的三条判断规则）：

1. **写入范围互斥** —— 六项各自的路径集合两两不交：`components.css`+`tokens.css`（W0）／五个各自独立的 `.html`（W1~W5）／`style-spec.mjs`+`index.html`+两处 MD 口径行（W6）。同一路径不出现在两个工作项里。
2. **共享契约已冻结** —— 契约 = F1~F11。其中 F1~F9 是仓库既有、本轮不改；F10/F11 由本文冻结。**唯一的松动点是 W2 的"边"与 W3 的"新建样式边界"**，两者都已给暂定口径并各自隔离在单页内，不影响他人。
3. **验收可机械判定** —— V1~V9 逐页人可机械判（操作一遍即可）；V10 需要 W6 先出页。W6 之所以**不能并行**，是因为它同时缺②（依赖 W0 冻结的类名）且有 ③ 的时序依赖（页不存在 ⇒ 索引链接 404）。

### 建议并行路数

- **第一波：6 路** —— W0 + W1~W5 同时开（W0 必须先落类名，或与页面作者约定好类名后并行；**类名一旦约定即视为冻结**）。
- **第二波：1 路** —— W6 单独跑，跑完由负责人**复核最终 diff**（确认只有 `index.html` + 四份文档变动、34 页可点开）。
- **总路数建议：6**（受限于 W0 是共享前置；若把 W0 拆成"进度环"与"五组布局件"两半，可提到 7，但会让 `components.css` 出现两个写入者 ⇒ **不建议**）。

### 交给"设计"阶段的一句话

按 §7 的口径、§8 的冻结输入、§9 的逐页要求、§10 的公共件清单做；先落 W0 的类名，再五页并行，最后 W6 统一出页；**本轮只要形态，不接数据、不动产品代码**。两处开口（② 的边、③ 的新建样式边界）按本文暂定口径走，在页面 `.note` 里标注清楚，等你看完形态再定。
