## 2 中心原则与筛除线

### 2.1 中心原则（原文）

> **目录页是并列展示。** 九个项目之间没有先后、没有依赖、没有强弱；"站数 / 下一站"只是每个项目**自己**的属性，不是项目之间的关系。
> —— 负责人 2026-10-16

### 2.2 筛除线（不满足直接出局）

| # | 出局形态 | 为什么出局 |
|---|---|---|
| S1 | "先 → 后"的**推进箭头**（流水线 / 时间带 / 看板） | 把并列改成了有向推进 |
| S2 | "谁连谁"的**连线**（接线图、散射节点的**边**） | 连线即声明项目之间的依赖或因果 |
| S3 | "谁更重要 / 更多"的**排位**（排行榜 / 大小分档 / 远近分档） | 位置或尺寸一旦编码权重，就产生了强弱 |
| S4 | "必须按顺序走完"的**强约束**（关卡 / 解锁链 / 逐级开放） | 给用户强加顺序，且与"游客可任意进入"冲突 |

**S2 的边界要说清**（最容易误伤的一条）：筛除的是**项目与项目之间的边**。"用户当前在看哪一格"是**观看关系**，不是内容关系，不在筛除线内；站点线（T1 验收标准③要求对齐的那套视觉语言）画的是**同一个项目内部**的站与站，也不在筛除线内。

**留在场上的只能是：并列关系不变，动的是呈现与反馈。**

### 2.3 本方案对筛除线的自查

水平环在上表四条上都成立：环没有箭头（不撞 S1）、环上不画项目之间的连线（不撞 S2）、位置只表示"当前看哪一张"而非权重（不撞 S3）、任意一张都能直接进入（不撞 S4）。展开见 §3.2。

## 3 唯一候选 v1：水平环形伪三维卡片（旋转木马）

> 以下 §3.1~§3.7 每条均为**负责人已拍板**或以其口径推导。凡未定的不加默认值。

### 3.1 机制

卡片沿**水平圆周**排成一圈（旋转木马），前后遮挡、左进右出，**焦点卡片位于前方正中**；通过**旋转环**来切换焦点，点击焦点卡片进入该项目。

### 3.2 为什么它过筛除线（并列语义）

环是**可循环的闭环**，不是链式队列：没有"第一张/最后一张"，顺转与逆转都回到同一组项目。因此**位置不承载先后关系**，只承载"当前看哪一张"。

与 S3 的关系：环上每一张卡的**尺寸差异来自它在环上的角度**（离前方正中越远越小），而角度是**观看位置**、不是项目自身的权重；任何一张转到前方正中都会获得同样的尺寸与焦点态。**这层论证已由负责人认可（2026-10-16，D18 / §6-17）**。

**"卡片不随环转"对筛除线的帮助（D13）**：卡片**始终面向视口**（不随环切线转动）⇒ 卡片之间只有"远近 / 大小 / 清晰度"的差异，**没有任何一张卡以"角度"呈现方向性或层级**，位置编码的语义只剩"当前看哪一张"。

### 3.4 交互（据 D3 / D4 / D7 推导，供后续阶段展开）

- **拖拽 / 滚轮转动环**；松手后按速度**惯性滑行**，阻尼减速，最后**吸附到最近卡片**。
- **焦点卡片** = 离前方正中最近的那张；**拖动过程中焦点可实时更替**。
- **悬停焦点卡片微抬**——这是 T1 验收标准①「三类反馈」里的一类。
- **←/→ 移一格、Enter 进入**；焦点环**只在键盘模态画**。
- **触控**：拖拽必须可用；触控下"环旋转"与"页面 / 面板滚动"的冲突处理**转设计阶段实测**（可测的环境现象，不是偏好题；见 §6-8）。

**三类反馈（T1 验收标准①）在本方案里的落点**（**建议**，口径取自既有网格卡片的现成写法；其中"悬停"已由 D14 补强，取值本身仍属设计）：

| 反馈 | 本方案落点 | 既有先例 |
|---|---|---|
| **悬停** | 焦点卡微抬 + 描边变主色 | 网格卡片的 hover 口径 |
| **选中 / 当前** | 焦点卡（位于前方正中者）得选中态：主色描边 + 弱主色底 + 主色辉光 | 网格卡片的 `--active` 口径 |
| **进入** | 点击焦点卡后给一次短暂推进过渡，再进项目 | 页面级过渡时长令牌 |

> 上表三行的**具体取值**属设计阶段（本文不定值）。一处**规则冲突**（焦点卡的"选中态"若用**辉光 / 阴影**表达，会撞框体规则"中性描边与 elevation 阴影不得同时用"，而焦点卡还要画 0.5px 发丝）：**负责人 2026-10-16 裁定交给设计阶段**——它是**观感问题**（D22 / §6-22），本文不选。

### 3.5 窄屏退化

**已拍（D16）：窄屏改「垂直滚动」，"也是环"** —— 窄屏下的形态是**垂直方向滚动的环**，**不是**单列列表、**不是**分页条、也不是"透视收到最小的横排"。

- **与 D1 的关系（必须写清）**：D1 定的是**水平圆环**（桌面主形态）；本条是它在该窗口下的**降级形态 = 垂直环**。**不要**读成"换了个方案"、更不是"又一个候选"——**同一个方案，两种朝向的形态**。

### 3.6 技术路径（**方向性，不是实现方案**）

纯 DOM + CSS `transform`（`perspective()` / `translateZ` / `rotateY`）+ scroll / pointer 监听；**不引入 3D 库**；卡片的权重（尺寸 / 模糊 / 透明度）由"**距前方正中的角度**"映射得出。

- 这是**方向**，不是设计定稿：具体类名、DOM 结构、令牌取值、角度→权重的映射公式，都属设计阶段产出，本文不写（写了就等于越阶段定值）。
- "不引入 3D 库"与仓库既有做法一致：排版稿页面一律零第三方库、脚本一律内联（上一版五页也是这么做的），**本文只沿用这条纪律，不引它的类名或结构**。

### 4.1 环的半径 / 焦点卡尺寸（→ §6-1，**仍待设计阶段定档**）

已知的**已拍结果**是"一屏 5~6 张"（D2），不是几何量。半径与卡宽是一对**互相牵制**的量：一屏能露几张卡由"环上相邻卡的角间距"与"卡宽 / 环半径之比"共同决定。

| 候选取向 | 后果（推断） | 与其他已拍项的关系 |
|---|---|---|
| 环半径大 / 卡尺寸不变 | 一屏露出的卡数偏多、单卡在环上的角度差变小 ⇒ 远近差异**弱**，"前后遮挡"几乎看不出 | D2 要求只露 5~6 张 ⇒ 半径有**上界** |
| 环半径小 / 卡尺寸不变 | 相邻卡的角度差变大 ⇒ 远近差异**强**、遮挡明显；但远端卡片缩小得快，与 C4（命中区）压力更大 | 与 D5 的"三项同时衰减"叠加后，最远一张可能近乎不可见（见 §6-5） |
| 半径小 + 卡也小 | 单卡可读面积下降（卡片要放项目名 / 站数 / 下一站 / 视觉主体） | 站点线导航的可读性口径 |

> **本文不做的事**：不给具体数值（px / vw / 角度）。**建议**：在负责人定档之前，先确定"最小可读卡宽"与"最小命中尺寸"两个下界（后者见 §6-20），再反推半径——**这只是一个次序上的建议**。

### 4.2 卡片是否随环转动朝向（→ §6-2）—— ✅ **已拍板：始终面向视口（D13）**

**结论**：负责人 2026-10-16 选定**始终面向视口**（卡片法线永远指向观众）。下表保留作追溯。

| 候选 | 观感（推断） | 连带影响 |
|---|---|---|
| **始终面向视口**（卡片法线永远指向观众）← **已选** | 读得清，像"一圈挂牌"；远近只由尺寸 / 模糊 / 透明度表达 | 卡片始终是"正面朝我"，透视感主要来自尺寸与模糊；**C2（发丝忽粗忽细）与 C3（圆角拉伸）随之不成立** |
| **随环切线转动**（像真旋转木马，卡片面朝环外侧） | 立体感强、转动时卡片侧面掠过，动感更足 | 侧向卡片近乎"一条线"，可读性下降；C2、C3 **必然出现**；命中区（C4）更难判；D5 的三项衰减还要与"侧面变窄"叠加 |

> **已选此案的后果**：C2 / C3 两条冲突**结案**（§3.7）；卡片不需要"侧面"表现 ⇒ 省掉一层透视计算的复杂度。**焦点环与选中态**仍要在正面上处理（§6-22，交设计）。

### 4.3 环的倾斜角（→ §6-3，**仍待设计阶段定档**）

D1 只定了"**水平**"，没定是否有俯角。

| 候选 | 观感（推断） |
|---|---|
| 完全水平（俯视平面即为屏幕平面，即无俯角） | 与现有横向卡片网格最接近；远端卡片"往里退、往上一点点"的立体感**主要靠缩放**，而不是靠几何倾斜 |
| 带一点俯角 | 能看到环的"纵深走向"，更像个台面 / 圆桌；但环的上下边缘与页面其他元素（页眉浮卡、提示条）抢高度，纵向排版空间变小 |

> 与 §6-4（纵向位置）是**一对**：俯角越大，环在垂直方向占的高度越多，"居中还是偏上"的余量越小。
