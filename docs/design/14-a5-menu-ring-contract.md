### 4.3 环半径与角距（设计定）

| 项 | 取值 | 推导 |
|---|---|---|
| 环半径 R | **600px** | 见下方推导 |
| 相邻卡角距 Δ | **24°** | 见下方推导 |
| 环上卡片数 | **9**（固定） | F15 |

**推导（可复核的算术）** —— 三个量互相牵制，**先给出两个上界，再给设计定的取值**（不要读成"联立解出"）：

1. **槽位间距**（`k=0` 与 `k=1` 这两张相邻卡的中心水平距，**只有这一对**等于它）：`slot₀₁ = 2R·sin(Δ/2)`。
2. **首尾相接**要求 `9 × Δ ≤ 360°` ⇒ **Δ ≤ 40°**。后面各对的间距**不是**常数（见 §4.3 的 `d(k)` 表：逐对差值是 249.6 / 211.1 / 110.0 / 83.9 —— 环越往两侧越"挤"）。⇒ **凡是要用"间距"的地方（拖拽换算、定位），一律用 `d(k)` 表，不要用 `slot` 当常数。**
3. **相邻卡要重叠一次**（F1 的"前后遮挡"在几何上必须真的发生）：`slot₀₁ < w(0)/2 + w(1)/2`，其中 `w(k) = 360 × scale(k)`（§5.2）。代入 `w(0)/2 = 180`、`w(1)/2 = 153` ⇒ `2R·sin(Δ/2) < 333`。**Δ = 24° 时给上界 `R < 801`。**
4. **同屏 5 张**要求最远的那个可辨档位（档位 3，`k=3`）不越出画布：`R·sin(3Δ) + w(3)/2 < 960`（半画布宽）。`Δ=24°` 时 `sin72° = 0.9511`、`w(3)/2 = 109.8` ⇒ `0.9511·R < 850.2` ⇒ **上界 `R < 894`。**
5. **两条上界的交集**：`R < 801`（更紧）。⇒ **`R` 的可行区间是 `R ∈ (下界, 800)`。**
6. **取 `R = 600` 的理由（这是设计定，不是解出来的）**：上界只说明"不能多大"，**下界**才是取值依据 —— `R` 越小，环的横向铺开越窄、相邻卡叠得越狠；`R` 越大，环读起来越像一排摊开的牌（遮挡感消失）。取 600 时 `slot₀₁ = 249.6`，相邻卡的**中心距不到两张卡半宽之和（333）** ⇒ 遮挡真的发生（重叠 83px，见 §4.3.1），且环的横向铺开到 `±780`（§4.5），在 1920 画布里**刚好铺满而不越界**。⇒ **600 是"遮挡够明显 + 铺展够满 + 不越画布"三者之间的设计取值。**
7. `Δ = 24°` 同样是**设计定的偏紧值**（不是 9 张均分 360° 的 40°）：40° 时 `slot₀₁ = 410`，`410 > 333` ⇒ **相邻卡不再重叠**，环会读成"九张摊开的大牌"，遮挡感消失。⇒ **实现不得改成 40° 均分。**

**⇒ 采用的取值：`R = 600px`、`Δ = 24°`。**

**由此推出的几何事实（实现照此，不要另算）**：

| 量 | 值 | 算式 |
|---|---|---|
| 环周长 | 3769.9px | `2πR` |
| 槽位间距 `slot₀₁`（**只有 `k=0↔1` 这一对**） | **249.6px** | `2·R·sin(Δ/2)` |
| 第 k 档卡中心距环心投影 `d(k)` | **0 / 249.6 / 460.7 / 570.7 / 654.6 px** | `R·sin(kΔ)`（k = 0..4） |
| **逐对间距**（相邻两档中心的水平距） | **249.6 / 211.1 / 110.0 / 83.9 px** | `d(k+1) − d(k)`；**不是常数** |
| 环的横向包围盒 | `±(d(4) + w(4)/2) = ±759` ⇒ **在 1920 画布内**（±960）；仍由 `.a5r-ring` 的 `overflow: hidden` 收口 | §5.3 |
| 与"一屏 5~6 张"的关系 | 档位 1 完整（360px）+ 档位 2 露 223px + 档位 3 露 188px ⇒ **5 个可辨卡位**；旋转中档位 5 替换进来 = 第 6 张 | §4.3.1 的逐张表 |

> **⚠️ 一处最容易写错的地方**：`slot₀₁ = 249.6` **只对第一对成立**。环越往两侧，`d(k)` 的增量越小（因为 `sin` 在 90° 前趋于平缓、过了 90° 回落）⇒ 逐对间距从 249.6 掉到 83.9。**所以脚本里不能用"`dx / 249.6`"当通用换算去定位**。可行的近似只有一种：**整排按"转动角"平移**（环整体转过一格时，每个卡位的承轴位移都等于 `slot₀₁`）—— 而**定位**必须用 `d(k)` 表逐档给值。这一条见 §7.2。

**为什么不是"9 张均分 360°"（Δ = 40°）**：Δ=40° 时 `slot₀₁ = 410 > 333`（= 两张卡半宽之和）⇒ **焦点卡与档位 2 不再重叠**，遮挡感消失、更像"九张摊开的大牌"。**Δ = 24° 是有意选的偏紧值**，实现不得改成 40° 均分。

**必读的一条**（否则后面的预算会算错）：`--a5r-scale` 是 **`transform: scale()`（视觉缩放）**，**不改变元素在布局里的占位** ⇒ 卡片的**占位宽恒为 360px**，屏幕上的宽度才是 `360 × scale`。⇒ 实现必须用 `position: absolute` + 按 `d(k)` 显式定位（**不要**用 `flex` 让浏览器按 360px 排开，那会得到 249.6px 间距下的**大面积布局重叠**，与"视觉重叠"不是一回事）。

**5~6 张是怎么数出来的（逐张点清，免得实现自己重算）**：

| 档位 | 屏幕中心 x | 屏幕宽 | 屏幕区间（x = 中心 ± 半宽） | 露出情况 |
|---|---|---|---|---|
| 1（焦点） | 0 | 360 | −180 ~ +180 | **完整**（360px） |
| 2 | ±249.6 | 306 | 97 ~ 402（右侧为例） | 被档位 1 盖住左侧 83px ⇒ **露出 223px** |
| 3 | ±460.7 | 259 | 331 ~ 590 | 被档位 2 盖住左侧 71px ⇒ **露出 188px** |
| 4 | ±570.7 | 220 | 461 ~ 681 | 被档位 3 盖住左侧 ⇒ **露出 110px**（opacity 0.28，读作"环继续转过去"的暗示） |
| 5 | ±654.6 | 209 | 550 ~ 759 | 与档位 3/4 叠在一处，**静止时几乎不可辨**；旋转过程中它替换进来成为新的档位 3/4 |

⇒ **静止态可见 = 档位 1（整张 360px）+ 档位 2（223px）+ 档位 3（188px）= 5 个可辨的卡位**（另加档位 4 那 110px 的淡影）；旋转中档位 5 替换进来。**这正是 D2 的"只露前方 5~6 张"**（第 6 张是旋转过程的过渡态），也解释了为什么 §5.2 的档位表在档位 5 要压到下限（它是"边缘提示"，不是内容）。

### 4.4 环的倾斜角：**完全水平，无俯角**（设计定，对应上游待定 2）

| 候选 | 本文选择 | 理由 |
|---|---|---|
| 完全水平（俯视平面 = 屏幕平面） | **选** | ① 与 F9「卡片始终面向视口」自洽：无俯角时"环的纵深"只能由**尺寸 + 模糊 + 透明度**表达 —— 正好是 D5 要求的三项，不会多出第四种表达（几何倾斜）。② 俯角会**给环加一条纵向的"走向"**，而纵向走向在观感上容易被读成"前后顺序" ⇒ 与 F14「邻接 = 观看顺序」的边界贴得太近，属**主动回避反身性风险**。③ 俯角吃掉纵向空间（环的上下边缘要占高度），与 §4.5 的排布预算打架。 |
| 带一点俯角 | 不选 | 见上 |
| **实测判据** | 页面里**不得**给 `.a5r-ring` 或 `.a5r-card` 加 `rotateX`（也不得加 `perspective`）—— §12 V-C |

> **上游"一屏 5~6 张"（D2）的机械判据**：1920 画布下，**档位 1 的卡完整落在画布内**（360px 全见），**档位 2 与档位 3 各自至少露出 150px**（两对，共 4 张）⇒ 合计 ≥ 5 个可辨卡位。§12 V-G 会逐张量这一条。

> **关于 `perspective`：本文定「不用」**（`perspective: none`）。
> 理由（可复核）：在 `R = 600` 下，环的**深度极差只有 64px**（`k=0` 在焦平面、`k=4` 在 `600·(1 − cos96°) = 62.7` 之外）⇒ `perspective: 1400px` 能带来的最大几何缩放差仅 `1400/(1400−63) = 1.047`，即 **约 +5%**，而且这 5% 还要与 §5.2 的 `--a5r-scale`（档位 5 是 −42%）**叠加**，属于"同一个幅度被两个机制各表达一半"，会让"哪一层负责变小"这件事变成两处都要调。
> ⇒ **本文把纵深完全交给 §5.2 的尺寸 + 模糊 + 透明度三项**（这正是 D5 的要求），`perspective` 不参与。**实现不得**"顺手加一点 perspective 增加立体感" —— 那会让 §5.2 的档位表与实际观感脱钩，§12 V-C 会抓到。
> **注意**：这与 F9「卡片始终面向视口」并不冲突 —— 该条约束的是**卡片不得随环切线旋转**（禁 `rotateY`），与是否开透视投影无关。本文只是选择"不开"。

### 4.5 纵向位置：环心在正文带 **42%** 处（设计定，对应上游待定 3）

**正文带的定义**（这是几何基准，实现不得另取）：`docs/ui-mockups/mockup-shell.css` 的 `.board__body` —— 1920×1080 画布内、位于页眉浮卡之下的可用区。**在 A5 环形页里，正文带 = 画布整高 1080**，因为：

- `.board__body` 是 `flex: 1` + `position: relative`（`mockup-shell.css:39`），而三页手写页**不放 `.ui-statusbar`**（外壳骨架见 §11.1）⇒ 正文带 = 1080px 全高；
- 页眉浮卡是 `.board > .ui-titlebar` 的**绝对定位**（`mockup-shell.css:126-133`：`top: calc(50px - 28px) = 22px`、`left: 50px`、`max-width: min(600px, 100% - 100px)` ⇒ **水平占 50~650px、纵向占 22~92px**，且浮卡**不是**正文的兄弟遮挡源，是叠在上面的浮层）。

| 量 | 取值 | 复核 |
|---|---|---|
| 环心纵向 | **正文带上边起 42%** ⇒ `y_slot = 0.42 × 1080 = 453.6 ≈ 454px` | 见下方三条约束 |
| 约束① 眼睛高度 | 焦点卡中心落在画布纵向 42%（≈454px）而不是 50%（540px） | 教学界面的阅读中心略高于几何中心（既有先例：`components.css:1443` 的 `.a5v-stage__head` 把正文从 `--shell-top-y + --shell-bar-h + 10 = 130px` 起排） |
| 约束② 浮卡不压 | 所有档位的卡的**上沿最小到 198px**（见下表）；浮卡占 **22~92px** ⇒ 余量 106px，**不重叠** | `.board > .ui-titlebar` 的 `top: 22px`、高 70px（`mockup-shell.css:126-133`、`tokens.css:364`） |
| 约束③ 底部说明条不压 | 所有档位的卡的**下沿最大到 664px**（见下表）；`.note` 是 `left: 24px; bottom: 18px`、高约一行（`mockup-shell.css:58-61`）⇒ 占底部约 `1044~1062px`，**余量 380px** | 同上 |
| **纵向压缩系数** | **`--a5r-vscale = 0.5`** —— 环的**纵向**位置取"真实几何的投影 × 0.5"，**横向不压缩** | 见下 |

**为什么要纵向压缩（这是本文的一处显式设计选择，不是几何必然）**：真实几何下 `R·cos(kΔ)` 会把最侧的卡抬到 `454 − 600·cos(96°) = 454 + 63 = 517`、把 `k=4` 抬到 `454 − 600·cos96° = 517` 之外更远的位置（`k=3` 到 `454 − 600·cos72° = 268`、`k=4` 到 `454 + 63 = 517`，纵向摆幅 ±186px 起），**环的纵向摆幅会大到把最侧的卡顶进浮卡区或压到底部说明条上**。⇒ 本文把纵向摆幅**压到一半**（`0.5`），环读起来仍是一条**微微起伏**的带（这是"环"与"一排牌"的区别所在），但纵向不再与外壳抢空间。

**环上各档的纵向位置（冻结，实现照此）**：

```
y(k) = --a5r-slot-focus 的像素值(454)  +  (卡高/2) × scale(k)  −  R·cos(kΔ) × --a5r-vscale
```

即 `y(k) = 454 + 210·scale(k) − 300·cos(kΔ)`（`300 = 600 × 0.5`）：

| 档位 k | `--a5r-scale` | `y(k)`（卡中心的屏幕 y） | 该卡的纵向区间（`y ± 210·scale`） | 备注 |
|---|---|---|---|---|
| 0（焦点） | 1.00 | **454** | **244 ~ 664** | 就是环心（42% 位） |
| 1 | 0.85 | **425** | **247 ~ 604** | |
| 2 | 0.72 | **395** | **244 ~ 546** | |
| 3 | 0.61 | **359** | **231 ~ 487** | |
| 4 | 0.58 | **320** | **198 ~ 442** | 与档位 3 的纵向接近（`cos` 在 90° 附近趋于平缓） |

⇒ **所有档位的卡落在 `198 ~ 664`**：上沿最小值 198 > 浮卡下沿 92（余量 106px），下沿最大值 664 < 底部说明条上沿 1044（余量 380px）。**两条约束都成立。**

> **不得**把 `y(k)` 写成 `R·(1 − cos(kΔ))` 或 `R − R·cos(kΔ)` —— 那两种写法都把"环心"当成了 0，会把整排卡整体上移约 454px（顶进画布外）。**454 这个基座不是可有可无的常数**：它就是 `--a5r-slot-focus: 42%` 在 1080 画布上的像素值。
> **`--a5r-vscale` 必须显式写成变量**（不要把它折进 `y(k)` 的数字里）—— 垂直环形态（§11.3）要用它做另一套压缩，两处共用一个系数才好调。

> **实现注意（一处必须先钉死的基准）**：环心纵向**不得**用 `align-items: center` 让浏览器算 —— 必须显式给 42%。而且要**钉死 42% 的参照物**：`.a5r-ring` 必须 `position: absolute; inset: 0`（铺满 `.a5v-stage__body`），且 `.a5v-stage__body` 必须撑满到 `.board__body` 的整高 —— 既有 `.a5v-stage__body { flex: 1; min-height: 0 }`（`components.css:1445`）在 `.a5v-stage` 是 `height: 100%`（`:1436`）时**确实**会得到 1080 减去头部行高的高度，**不是 1080**。⇒ 两种做法都合规，但必须**二选一并写清**：
> - **做法 A（推荐）**：`.a5r-ring { position: absolute; inset: 0 }` 相对 `.board__body` 定位 ⇒ `42%` = **453.6px**（就是本文所有 `y(k)` 数值的基准），此时 `.a5r-ring` 需要挂到 `.board__body` 的直接子层上（`.a5v-stage` 允许多一个绝对定位子项，不影响头部行流式排版）；
> - **做法 B**：`.a5r-ring` 留在 `.a5v-stage__body` 内、也 `position: absolute; inset: 0`。此时 `42%` 的参照物变成"1080 − 头部行高（≈130px）≈ 950px" ⇒ 若仍写 `42%`，落点是 `950 × 0.42 = 399px`，**比本文的 454px 高 54.6px** ⇒ §4.5 的 `y(k)` 表与两条纵向约束**全部要重算**。若选 B，**必须把 `--a5r-slot-focus` 改成 `454 / 950 = 47.8%`**，让落点回到 454px。⚠️ 注意：**"42%" 这个百分数本身没问题，错的是参照物** —— 别把结论读成"42% 会变小"。
> **本文推荐 A**（数值基准唯一、不与头部行高耦合）。§12 V-D 会量这一条。

### 4.6 最小命中尺寸：远端卡片**不允许**小于 44（设计定，对应上游待定 6）

上游口径：44×44 沿用，只剩"远端卡片是否允许小于 44"这一小截。**本文裁定：不允许，且不需要例外。**

| 项 | 取值 | 复核 |
|---|---|---|
| 卡片可点区域（视觉区 = 命中区） | 焦点档 **360 × 420** → 最远档 **209 × 244**（`360×0.58 × 420×0.58`） | 两轴**都** > 44（最远档是 44 的 **4.7 倍**）⇒ **任何档位都不破线** |
| 结论 | **不给远端单独定值，不加"撑到 44"的补丁** | 209 × 244 离下界极远 |
| 远端卡片**是否可点** | 可点，但见 §8.4 的**档位门**：只有 `--a5r-scale ≥ 0.72`（k ≤ 2，档位 1~3）的卡进 Tab 序列 | 44 是**命中下界**、不是**可及性下界**；把已经糊掉、还被盖住一半的卡放进 Tab 序列才是可及性问题 |
| 评审外壳的例外 | 外壳自身的链接与页眉徽标**不算**页面内可点元素（13 §7 R8） | 与本节一起读，免得把外壳链接也算进整改 |

**一个必须写清的边界**：卡片的**命中区 = 卡片的 `getBoundingClientRect()`**，因为缩放由 `transform: scale()` 实现（**不是** `width` 变化）⇒ 浏览器**自动**把命中区一起缩放。**实现不得**用"给远端卡挂一个 44×44 的透明补丁元素"的做法 —— 那会让 9 张卡里出现 9 个无名可点元素，撞 §12 V-I 的可点元素清单核对。

## 5 远端衰减：档位、曲线与下限（D17 交设计，本文定档）

> F6 要求三项**同时**变化；F7 要求**作用于整张卡片**（一层整体）。本文把两项要求合成**一组令牌 + 一张档位表**。

### 5.1 只算一次的核心量

**方向判决**：焦点卡在**前方正中**（弧长 s = 0），离它越远 ⇒ 越靠后 ⇒ 越小、越糊、越透。**本文定义**（实现照此，不要反）：

```
off(i) = ((i − focus) % N + N) % N          // 0..N−1，环闭合（N = 9）
k      = off > N/2 ? N − off : off          // 0..4，N=9 时最大 4
档位    = clamp(k + 1, 1, 5)                 // 档位 1 = k=0（焦点档）
```

⇒ **焦点档是唯一"满血"档**，两侧对称衰减（`i = focus−1` 与 `i = focus+1` **同档**）。**这是 F14「邻接 = 观看顺序」的机械兑现**：左右对称就意味着"往前看"与"往后看"在视觉上等价，不产生方向偏见。

**其中 `focus` = 焦点卡的环序**（不是屏幕位置、不是 Tab 序）；`N = 9` 由 F15 固定，实现**不得**写成变量。k 的最大值 = 4（`floor(9/2)`）。

### 5.2 三项衰减的档位表（**冻结**）

> **档位号 = `k + 1`**（档位 1 是焦点档）；表中同时给出 **k、屏幕位置公式、屏幕宽度**，因为 §4.3 的槽位几何已经代入了这张表的 scale —— 两者必须一起读，**改一个就得改另一个**。

| 档位 | k | `--a5r-scale` | `--a5r-blur` | `--a5r-opacity` | `--a5r-z` | Tab 可及 | 卡片屏幕宽 × 高 | 屏幕中心 x |
|---|---|---|---|---|---|---|---|---|
| 1（焦点） | 0 | **1.00** | **0** | **1.00** | 500 | ✅ | 360 × 420 | 0 |
| 2 | 1 | **0.85** | **2px** | **0.72** | 400 | ✅ | 306 × 357 | ±249.6 |
| 3 | 2 | **0.72** | **4px** | **0.44** | 300 | ✅ | 259 × 302 | ±460.7 |
| 4 | 3 | **0.61** | **6px** | **0.28** | 200 | ❌ | 220 × 256 | ±570.7 |
| 5（最远） | 4 | **0.58** | **6px** | **0.28** | 100 | ❌ | 209 × 244 | ±654.6 |

**读表须知（四条硬口径）**：

1. **下限**（D17 问的"有没有最小值"）：**有**。档位 5 **不再继续变小变糊**，而是停在 **scale 0.58 / blur 6px / opacity 0.28**（档位 4 只比它大一点点：0.61 / 6px / 0.28）。理由：档位 4/5 在静止态各自只露出约 **110px / 78px** 的边缘（§4.3.1 的表），继续衰减只会让那一条糊成一团黑边，反而更像脏点。⇒ **这就是"最远一张允许低到什么程度"的答案：不允许低于 scale 0.58 / opacity 0.28。**
2. **scale 曲线为什么是这一条**：`1.00 → 0.85 → 0.72 → 0.61 → 0.58` 的前三档近似等比（每档 ×0.85），末两档**收平**。这是**有意让"越远越快变小"在前三档发生、在末两档停住** —— 前三档是用户真正要读的内容（§4.3.1），落差要够；末两档是提示，落差再大就只剩噪点。
3. **透明度下限 0.28 是"看得见有东西"的下界**：0.28 × `--glass-card` 的 α（深色 0.48 / 亮色 0.52，`tokens.css:166` 与 `:230`）≈ **0.13~0.15** 有效不透明度，在 `--bg-1` 上仍能读出卡的**轮廓**（发丝描边 0.5px × α 0.16 仍在）。**这一条是量级判断，不是精确计算** —— 实现时若发现最远档"看不见了"，优先调 `--a5r-opacity` 的 0.28（而不是把 blur 调小）。
4. **模糊下限 6px 的理由**：6px 在 360px 宽的卡上是"文字糊成一团块、但版面块状结构仍可辨"的量级；再往上（8~10px）边缘会出现"光晕外溢"，与 F7「一层整体变糊」的读感不符。**注意**：`filter: blur()` 会**外溢**到卡片边框之外 —— 这是接受的现象（外溢宽度与 blur 半径同量级，被 `.a5r-ring` 的 `overflow: hidden` 与 z-index 阶梯吸收），**不得**为消除外溢给 `.a5r-card` 加 `isolation: isolate` 或改 `overflow`（那会裁掉卡的圆角）。

### 5.3 层的秩序（前后遮挡怎么落地）

| z 值 | 谁 | 说明 |
|---|---|---|
| 500 | 焦点卡 | 永远在最前，**不被任何卡遮挡** |
| 400 / 300 / 200 / 100 | 档位 2 / 3 / 4 / 5 | 单调递减 ⇒ 靠前的盖住靠后的 |
| 变量 `--a5r-z` | 由脚本按档位写入卡片的**行内样式** | 实现不得用 `nth-child` 之类写死序号的规则（焦点会转，序号会动） |

> **为什么必须用 z-index 而不是只靠 DOM 顺序**：环是**闭合**的 ⇒ `k=4` 的卡在几何上"转到对面又转了回来"，它的 `d(4) = 654.6` 与 `k=3` 的 570.7 同侧相邻，**两者都会与 k=2 的卡重叠**。DOM 顺序无法表达"谁在前面"（顺序是固定的，焦点是动的）⇒ **只能由 `--a5r-z` 表达**。
> **为什么用 100 一档的间隔**：留出插入空间（例如将来给"进入过渡中的卡"临时抬一层，用 450 即可，不必重排全表）。

### 5.4 一条禁令（F7 的机械兑现，最容易被实现改坏）

> **禁止**给卡片的**任何子元素**单独写 `filter` / `opacity` / `transform: scale()`。
> 三者的唯一写入位置是 `.a5r-card` 本体（用 `--a5r-blur` / `--a5r-opacity` 变量）。
> 卡内元素（进度环、项目名、站数）**不得**有自己的缩放或模糊 —— 那就是 D6 明令否掉的"卡内分层（外层糊、内层不糊）"。

**唯一允许的例外**（且必须写清）：`.a5r-focusring`（§6.4 的焦点环）自带 `transform: scale(var(--a5r-ring-rescale))` —— 它的存在意义正是**反向补偿卡片缩放**，不是"卡内分层"。**除它以外没有第二个例外。**

### 5.5 焦点更替时的实时性

拖动过程中焦点**可实时更替**（13 §3.4）。⇒ 档位表必须在**每一帧**对 9 张卡重算并写入行内变量。**性能上不构成问题**：这是 9 次 `style.setProperty` + 1 次 `classList.toggle`，没有布局读取（**禁止**每帧 `getBoundingClientRect()`；旧 v1 页在这一点上已有先例与教训，见 `pages/a5-menu-v1-pseudo3d.html:296-301` 的注释）。

### 5.6 性能：本期**不设上限**（负责人 2026-10-16 裁决）

负责人原话：「**我明确 暂时不给上限 或者如果有逻辑门槛 就给一个肯定能通过的门槛**」。本文据此把 §4-10 处理成下面这样 —— **注意这是"放开"，不是"忽略"**：

| 项 | 本文口径 |
|---|---|
| 数值上限（帧耗时 / blur 面积 / 合成层数） | **不设**。实现阶段不得为凑预算而牺牲 F3（5~6 张）或 F6（三项衰减） |
| 仍然生效的**逻辑门槛**（必然能过，且是架构纪律） | ① `.a5r-ring` 的整排位移**只允许** `transform` 与 `opacity`；**禁止** `left` / `top` / `width` / `height` / `margin` 的过渡（会触发 layout，是整个方案唯一真正的性能陷阱）。② 三个手写页在 1920×1080 画布上**打开时不出现滚动条**（`.a5r-ring` 收 `overflow: hidden`）。③ 9 张卡**全部常驻 DOM**、不虚拟化（9 张的量级不需要）。 |

| 本文为什么不出数 | 本阶段只出文档、无浏览器可测；出数就等于**伪造**。这一点在 §13.3 再声明一次 |

## 6 三类反馈与选中态（T1 验收标准① / D22 交设计）

### 6.1 三类反馈总表（**冻结**）

| 反馈 | 类名（状态类，脚本挂/摘） | 视觉落点 | 取值 | 与另一类反馈怎么区分 |
|---|---|---|---|---|
| **悬停** | `.a5r-card.is-hover` | 卡**沿视口 Y 轴**微抬 + 描边变主色 | `--a5r-lift: -4px`（**只改变量**，由 §10.4 的 `transform` 串消费）+ `border-color: var(--accent)` | 位移量 4px；**不**变底色、**不**变尺寸 |
| **选中 / 焦点** | `.a5r-card.is-focus` | 内描边 + 同帧阴影 + 主色弱底 | 见 §6.3（三段式，**不用 `--glow-accent`**） | 有**底色**变化（`--accent-weak`），悬停没有 |
| **进入** | `.a5r-card.is-enter` | 一次短暂推进（放大） | `--a5r-scale` **额外 ×1.06**，`--dur-page` 后摘除 | 是**尺寸**变化，且**只持续 160ms**；前两类是稳态 |

> **三类必须互相不同**（T1 验收标准①的"明确"）：
> - 悬停 = **位移 + 描边**（无底色、无尺寸变化）
> - 选中 = **底色 + 内描边 + 阴影**（无位移）
> - 进入 = **尺寸**（160ms 内回落）
> ⇒ **三者没有共享任何一个视觉维度**，这是"明确"的机械判据（§12 V-J）。

### 6.2 悬停与惯性暂停的关系（D14，F10）

| 行为 | 口径 |
|---|---|
| 悬停任意卡片 | 环的**惯性暂停**（防误触进入） |
| 指针离开环区域 | **不立即恢复** —— 延迟 **`--dur-page`（160ms）** 后恢复，避免"擦着走过"被误判成停留 |
| 悬停时按 ←/→ 或拖拽 | **照常生效**（D14 暂停的是**惯性**，不是交互本身） |
| 悬停**最远档**的卡（Tab 不可及档） | **也给 hover 反馈**（鼠标用户不认档位门；门只服务键盘序列，见 §8.4） |

### 6.3 焦点卡选中态 × 描边规则（D22 交设计，**冻结**）

**冲突回顾**（13 §6-22）：焦点卡要画 0.5px 发丝描边（F17 §1），同时又要有"选中态"；若用辉光/阴影表达选中态，会撞 F17 §3 的「**`--border-*` 与 elevation 阴影不得同时用**」。负责人定性为**观感问题**，交设计。

**本文的解法：拆开"环"与"影"，各归各家。**

| 层 | 画什么 | 取值 | 为什么这样不撞规则 |
|---|---|---|---|
| ① 发丝描边（**不变**） | 卡片本体的 `border` | `0.5px solid var(--accent)`（选中时由 `--line-1` 换 `--accent`） | F17 §1：**主色**描边本就是允许的写法（`.ui-tile:hover` 就是这么做的，`components.css:139`） |
| ② 选中辉光 | `.a5r-card.is-focus` 的 `box-shadow` **内阴影**（inset） | `inset 0 0 0 1px var(--accent-weak), inset 0 0 24px var(--accent-weak)` | F17 §3 禁的是与 **elevation 族**（`--elev-panel` / `--elev-prominent` / `--elev-soft`，其第一层自带 `0 0 0 0.5px` 发丝）同用；**inset 阴影不承担边框职责**（它的 spread 是向内的一层色，不发丝），因此不与 ① 叠成双边框 |
| ③ 选中底色 | `background` | `var(--accent-weak)` | F17 §4：交互态"只叠一层半透明"；`--accent-weak` 就是既有选中态口径（`.ui-tile--active`，`components.css:140`） |

> **一句话交给实现**：**焦点卡 = 主色发丝 + `--accent-weak` 底 + `inset` 辉光**。**明确不用** `--glow-accent` —— 它是 `0 0 0 2px rgba(...)`（`tokens.css:115`），是**外扩**阴影，会与 0.5px 发丝叠出双边框，正是 §6.3 要避开的那个后果。
> **既有实现的偏差要说明白**：`.ui-tile--active` / `.ui-list__item--active` / `.ui-iconitem--active` 现在**就是**"`border-color: var(--accent)` + `box-shadow: var(--glow-accent)`"（`components.css:120`、`:140`、`:629`）。这是**既有 34 页的既有写法**，**本文不动它们**（改会全站一起变）；本条冻结只约束**环形卡这一个新组件**。⇒ 实现时**不要**为了让环形卡与 `.ui-tile--active` "看起来一样"而把 `--glow-accent` 加回来。

**焦点环在被缩放的卡面上的切割问题**（D22 的第二个子问题）—— 见 §6.4。

### 6.4 焦点环的画法（C5 的落地细节，**冻结**）

**问题**：卡片的缩放由 `transform: scale()` 实现 ⇒ 若焦点环画在卡片本体上（`outline`），环的**视觉粗细会随卡缩放**：焦点档 2px、档位 3（0.72）只剩 1.44px、档位 5（0.58）只剩 1.16px。远端卡的焦点环会糊到看不清 —— 而"档位 1~3 的卡都在 Tab 序列里"（§8.4 的档位门）⇒ **必须补偿**。

**本文解法**：环**不画在卡片本体上**，画在一个**自带反向缩放**的伪元素/子元素上。

| 项 | 口径 |
|---|---|
| 载体 | 类名 **`.a5r-focusring`**（由实现落成 `.a5r-card::after` 或卡内一个 `<span>`，**二选一，不要两个都做**） |
| 位置 | `position: absolute; inset: calc(-1 * var(--a5r-ring-pad)); border-radius: inherit` |
| 反向缩放 | `transform: scale(var(--a5r-ring-rescale))`，其中 `--a5r-ring-rescale = 1 / var(--a5r-scale)`（由脚本与 `--a5r-scale` 同帧写入） |
| 环本体 | `box-shadow: 0 0 0 var(--ring-width) var(--ring-color)`（**外扩**阴影；它**只**在键盘模态亮，见下） |
| 只画一帧状态 | 环**不参与过渡**（`transition: none`）—— 它是"焦点在哪"的指示器，不该有缓动（否则焦点已移、环还在路上） |
| 出现时机 | **只在 `html[data-input-modality="keyboard"]` 下可见**（F17 §5 / C5）。指针模态下 `--ring-color` 已被既有规则置为 `transparent`（`components.css:900`），因此**照既有机制走即可**，不必再写一条 |
| `--a5r-ring-pad` | `var(--ring-offset)`（= 2px） |

> **为什么可以用 `--ring-*` 令牌而不是 `outline`**：F17 §5 的原文是 `:focus-visible { outline: 2px solid var(--ring-color); outline-offset: 2px }`。本文的 `.a5r-focusring` 是**同一个语义的另一种实现**（因为 `outline` 无法反向补偿缩放），取值仍全部取 `--ring-width` / `--ring-offset` / `--ring-color`。⇒ **令牌口径一致，只是机制从 `outline` 换成反向缩放的 `box-shadow`**。这一条是本契约对 F17 §5 的**显式偏离声明**，实现时不要"顺手改回 `outline`"。

## 7 交互机制（D3 / D4 / D14 的落地）

### 7.1 状态机（实现照此）

```
        ┌──────────┐   pointerdown(主轴=横)   ┌──────────┐
        │  IDLE    │ ───────────────────────▶ │ DRAGGING │
        │(惯性可跑)│ ◀─────────────────────── │(惯性暂停)│
        └──────────┘   pointerup / cancel      └──────────┘
              │                                     │ pointerup(有速度)
              │ ←/→ 或 上/下                        ▼
              │                              ┌──────────┐
              └────────────────────────────▶ │ INERTIA  │  阻尼减速
                                             └──────────┘
                                                   │ 速度 < 阈值
                                                   ▼
                                             ┌──────────┐
                                             │  SNAP    │  吸附到最近格
                                             └──────────┘
                                                   │ 到位
                                                   ▼
                                                 IDLE
```

| 状态 | 进入条件 | 退出条件 | 期间焦点是否更替 |
|---|---|---|---|
| `IDLE` | 初始 / 吸附到位 | 拖拽、键盘、惯性 | 否（稳态） |
| `DRAGGING` | `pointerdown` 且主轴判定为横（§7.5） | `pointerup` / `pointercancel` | **是，实时更替**（13 §3.4） |
| `INERTIA` | `pointerup` 时**有速度**（\|v\| > 阈值） | 速度衰减到阈值以下（阻尼） | **是，实时更替** |
| `SNAP` | 惯性结束 / 键盘移焦点 / 拖拽位移不足一档 | 落位 | 是（终点即焦点） |

**悬停暂停（D14）落在哪**：`hover` 命中时，`INERTIA` ⇒ 立即切 `SNAP`（用户一碰就停）。这既兑现 F10，又保证"悬停不会停在一个非整数格上"。

### 7.2 拖拽（D3 的"手动拖拽"）

| 项 | 口径 |
|---|---|
| 事件 | `pointerdown` / `pointermove` / `pointerup` / `pointercancel`（挂在 `.a5r-ring` 与其祖先 `window` 上，**不用 pointer capture**） |
| 为什么不用 capture | 旧 v1 页有先例与教训：capture 会把卡片的 `click` 目标改到容器上（`pages/a5-menu-v1-pseudo3d.html:385`） |
| 位移映射 | 拖拽量 `dx`（px）⇒ 环转过的**格数** `Δn = −dx / var(--a5r-slot)`（`--a5r-slot` = 一格在**承轴**方向的屏幕位移；水平形态是横向 249.6px、垂直形态是纵向 249.6px，§11.3）。⇒ **整排按"转动角"平移**是可行的近似（环整体转动时每格的承轴位移都等于 `--a5r-slot`），但**定位必须用 `d(k)` 表逐档给值**，不能用 `--a5r-slot` 乘档号（§4.3 已说明逐对间距不是常数） |
| 实时反馈 | 每帧按 `Δn` 重算 `focus`（取最近格）并按 §5.2 写 9 张卡的档位变量（`--a5r-scale` / `--a5r-blur` / `--a5r-opacity` / `--a5r-z` / `--a5r-ring-rescale`） |
| 松手 | 记录最近 ~100ms 的速度 ⇒ 进 `INERTIA`（D4） |
| 拖拽后的点击抑制 | 拖拽位移 > 6px ⇒ **吞掉**随后那一次 `click`（阈值照旧 v1 页的 `dragMoved > 6`，`pages/a5-menu-v1-pseudo3d.html:366`） |
| 光标 | `.a5r-ring { cursor: grab }`；`DRAGGING` 期间 `cursor: grabbing`（由 `.a5r-ring.is-dragging` 切） |

> **为什么不用滚轮**：D3 的两条路径是"**手动拖拽**"与"**键盘**"。旧 v1 页有滚轮换焦点（`pages/a5-menu-v1-pseudo3d.html:374-383`），**那是作废实现**（它的机制是水平轴滚动，环不需要）。⇒ 环形页**不实现滚轮换焦点**；滚轮留给页面本身（环不吸滚轮）。

### 7.3 惯性滑行（D4）

| 参数 | 取值 | 说明 |
|---|---|---|
| 初速度 | `pointerup` 前最近 **100ms** 的平均速度（px/ms） | 采样窗口 100ms 是"够短以反映瞬时意图、够长以抗抖动"的量级 |
| 启动阈值 | `\|v\| ≥ 0.15 px/ms` 才进 `INERTIA`，否则直接 `SNAP` | 慢速松手 = 只想挪一格，不该滑 |
| 阻尼 | 每 **16ms** 帧 `v ← v × 0.92` | 指数衰减；`0.92` 下约 **28 帧（≈450ms）** 速度降到 1/e —— 教学界面不做演出感（与 `tokens.css` §22 的取值气质一致） |
| 停止阈值 | `\|v\| < 0.02 px/ms` ⇒ 切 `SNAP` | |
| 时长上限 | **1200ms** 硬上限（即使没衰减到阈值也强制停） | 防"甩一下飞很久" |
| 实现方式 | `requestAnimationFrame` 循环；**只写 `transform` 与 CSS 变量**；不在循环里读布局 | §5.6 的逻辑门槛 ① |

### 7.4 吸附（D3 / D5）

| 项 | 口径 |
|---|---|
| 目标 | 离环序 `focus` 最近的整数格（浮点 `focusFloat` ⇒ `Math.round`） |
| 过渡 | `transform var(--dur-page) var(--ease-page)`（**只认既有令牌**，不写零散时长 —— F17 §10 / `tokens.css` §22 的纪律），由 `.a5r-track.is-snapping` 这个状态类挂上 |
| 持续时间 | `--dur-page` = 160ms |
| 与拖拽/惯性的关系 | `DRAGGING` / `INERTIA` 期间**不加** `is-snapping`（每帧直接写值，不要过渡，否则会拖尾）；进入 `SNAP` 时挂上，落位后摘掉 |

### 7.5 触控拖拽 vs 页面 / 面板滚动（上游待定 5）

> **负责人 2026-10-16 裁决：先实现再说。** ⇒ 本节冻结**机制与语义**（保证实现有确定做法、且不会与既有纪律打架），**实测数据与最终调参归实现阶段**。

**为什么这一条不是"偏好题"**：环形页的拖拽是**水平**手势，页面/面板的滚动主要是**垂直**手势。两者在触控上的冲突只发生在"斜向手势"这一窄区间，因此可以用**轴判定**明确归属，而不是靠调参数。

| 项 | 冻结口径 | 理由 |
|---|---|---|
| `.a5r-ring` 的 `touch-action` | **`pan-y`** | 显式声明"纵向归页面滚动、横向归我"。既有的环形页**没有**对 `touch-action` 的约定，本条是新增（B 档冻结） |
| 主轴判定 | `pointerdown` 后积累位移，当 `\|dx\| > \|dy\| × 1.2` 且 `\|dx\| > 8px` 时**进入 `DRAGGING`**；若先满足 `\|dy\| > \|dx\| × 1.2` 且 `\|dy\| > 8px`，则**放弃本次拖拽**（交给页面滚动） | 1.2 的偏置比是为了让"几乎纯横"的手势才被判成拖拽，避免与纵向滚动反复抢 |
| 判定前的行为 | **不 `preventDefault`** | 判定期内不阻断，滚动才能正常起势 |
| 判定后的行为 | 进入 `DRAGGING` 后，`pointermove` 上 `preventDefault()`（并保持 `passive: false`） | 阻止已起势的纵向滚动被带走 |
| 多指 / 缩放 | 忽略（`pointerdown` 只认第一个 `pointerId`） | 本页无缩放手势 |
| 触控下的悬停反馈 | 触控**没有** hover ⇒ 三类反馈的"悬停"在触控下退化为 `:active` 按压反馈（`--inter-active`） | T1 验收标准① 在桌面评审；触控只保证"可用"（13 §3.5） |
| 实测动作（实现阶段） | 若实测发现"斜向手势被判成拖拽，页面滚不动"⇒ **优先调 8px / 1.2 两个判定阈值**，**不要**改 `touch-action`（改成 `none` 会让整个正文带滚不动） | 这一条是**留给实现阶段的唯一可调项** |

### 7.6 reduced-motion 具名豁免（D19 交设计，**冻结**）

**上游约束**（13 §3.3b 的机械约束）：全局兜底是 `components.css:913-919` 的**带 `!important` 的通配选择器** —— 「任何局部选择器都盖不过它」。⇒ 要让菜单卡片"时长不被压"，**必须**在**同一份**媒体查询里、用**同样带 `!important`** 的具名选择器覆盖。

**本文按负责人裁决取「最小作用域」**：

| 项 | 冻结口径 |
|---|---|
| 页面外壳类名 | 三个页面与产品页的环形容器**都**加一个 **`.a5r`** 类（挂在 `.a5r-ring` 的**父**元素上，作为作用域根） |
| 豁免类名 | **`.a5r--motion`** —— **只加在承载"惯性 / 吸附"过渡的那一个元素上**（即 `.a5r-track`，负责整排位移与吸附过渡）。**不要**加在 `.a5r` 上、**不要**加在 `.a5r-card` 上 |
| 写在哪 | `components.css` 的 **§26 末尾**，**单独一条** `@media (prefers-reduced-motion: reduce)`（集中一处便于复核；**不是**因为顺序有影响，见下面"为什么特异性够"） |
| **规则形态（关键：选择器里不得有 `*`）** | 只写一条选择器、**只重置时长**：<br>`@media (prefers-reduced-motion: reduce) { .a5r-track.a5r--motion { transition-duration: 160ms !important; animation-duration: 160ms !important; } }` |
| **为什么不能写 `.a5r--motion *`** | `.a5r-card` 是 `.a5r-track` 的**直接子元素** ⇒ 一旦带上 `*`，豁免就会**命中每一张卡**，把三类反馈的过渡从 `0.01ms` 改成 `160ms` —— 那就**超出了"最小作用域"**，与下一行的边界声明直接矛盾。**这是本契约里最容易写错的一条，§12 V-S 会抓。** |
| 为什么特异性够（不靠书写位置） | `*` 的特异性是 **0-0-0**，`.a5r-track.a5r--motion` 是 **0-2-0**；两者都带 `!important` 时**特异性高者胜**（与书写位置无关）⇒ 这条豁免**放在哪都生效**，不存在"必须紧跟全局兜底之后"的要求 |
| 为什么是 `160ms` 而不是"沿用原值" | `!important` 覆盖只能给**固定值**（不能写"恢复成原来那条规则的值"）⇒ 取 `--dur-page` 的字面值 **160ms**（`tokens.css:411`），并在规则旁**原样写出注记** `/* = tokens.css:411 --dur-page */`。若将来 `--dur-page` 改了，这里要跟着改（**已在 §13.2 登记为唯一需要跟改的硬编码**） |
| **作用域边界（这条最重要）** | 豁免的**只是** `.a5r-track` 上那一条过渡（整排位移 / 吸附）。⇒ 三类反馈的 `transform`（含 `--a5r-lift`）/ `border-color` / `background` 过渡**仍落在 `*` 兜底的覆盖范围内**（它们作用在 `.a5r-card` 上，而豁免选择器**不命中**它），该档下表现为**瞬切** —— 这正是"最小作用域"的字面含义，**不要**为了让三类反馈也动起来而扩大豁免 |
| `.a5r-focusring` | 它本来就 `transition: none`（§6.4），**不受**本条影响，也**不得**被本条改成有过渡 || 静态是否换形态 | **不换形态**（D11 已取消"另定该档静止形态"这条要求）。⇒ 该档下环仍可拖、仍可 ←/→ 移焦点、仍可进入；只是吸附与惯性的**过渡时长**是 160ms |
| 违反后果 | ① 若写成 `.a5r--motion *` ⇒ 三类反馈被一起豁免 = **超出最小作用域**（§12 V-S 会抓）；② 若在**别处**新增 media query ⇒ 撞 F19「不许各自写媒体查询」；③ 若写 `animation-duration: 0s` ⇒ 变成瞬切，与"菜单卡片动画不受压缩限定"的意图相反 |

### 8.1 键位映射（**冻结**）

| 键 | 水平环（桌面主形态） | 垂直环（窄屏降级形态） | 说明 |
|---|---|---|---|
| `ArrowLeft` | 焦点 **−1 格**（环闭合） | **同左**（−1 格，向上） | 见 §8.3 |
| `ArrowRight` | 焦点 **+1 格**（环闭合） | **同右**（+1 格，向下） | 见 §8.3 |
| `ArrowUp` | **−1 格**（等价 `ArrowLeft`） | **−1 格**（主键） | 增补 |

| `Enter` | 进入焦点卡 | 同 | F8 |

**焦点跟随**（C5 的可见性要求）：任何一次键盘移焦点，**必须**同时让环把该卡转到**前方正中**（不只是"画个环"）。⇒ 键盘移到屏外的卡上是不可能的（旧 v1 页把这一条明确写成了需求，见 `pages/a5-menu-v1-pseudo3d.html:312`）。

### 8.2 环闭合的邻接表（**冻结**，9 项逐条写明）

> 上游 13 §8.3（旧版）有一条经验：邻接**必须显式写出来，不能靠坐标算术猜**。环形页的邻接很简单（一维环），但本文仍逐条列出，避免实现时"顺手写成 clamp（夹紧）"。

| 环序 i | 项目 | ←/↑ 去到 | →/↓ 去到 |
|---|---|---|---|
| 1 | 接触器 | **9**（小测验） | 2（热继电器） |
| 2 | 热继电器 | 1 | 3 |
| 3 | 时间继电器 | 2 | 4 |
| 4 | 主令电器 | 3 | 5 |
| 5 | 熔断器 | 4 | 6 |
| 6 | 断路器 | 5 | 7 |
| 7 | 速度继电器 | 6 | 8 |
| 8 | 组合开关 | 7 | **9** |
| 9 | 小测验 | 8 | **1**（接触器） |

**公式**：`next = ((i − 1 + d) % 9 + 9) % 9 + 1`，`d ∈ {−1, +1}`。**首尾相接的两格（9↔1）必须是真的接得上**，不是禁用。

**这条邻接的语义**（F14）：它表示**观看顺序**——"我现在顺着环再往下看一张"。**不表示**"小测验是接触器的下一步"、也不表示任何内容依赖。⇒ 实现时**不要**在页面上画出弧线箭头、不要写"下一个项目"这类文案（那会把观看关系读成内容关系，撞筛除线 S1）；允许的文案是「环上移一格」。

### 8.3 垂直环下的键位（上游待定 9，**冻结**）

| 方案 | 本文选择 |
|---|---|
| 只保留 ←/→ | 不选 —— 窄屏（触控为主、外接键盘少见）用户看到的是**纵向**排列，用左右键"上下走"违反直觉 |
| **←/→ 保留 + ↑/↓ 增补**（两套都收） | **选**。理由：① **同一份代码**在两种朝向下都可用（垂直环只改"环在哪个平面上转"，键位映射表**不变** ⇒ 不必为朝向写条件分支）；② 仓库已有先例：旧 v1 页同时接受方向键与横竖两组键（`pages/a5-menu-v1-pseudo3d.html:359-360`）；③ 冗余键位不产生歧义（两套指向同一状态机），而"砍到只剩 ↑/↓"会在水平环下让 ←/→ 失效 —— 那才是真的坏 |
| 只保留 ↑/↓ | 不选 —— 见上第 ③ 条 |

> ⇒ §8.1 的键位表在**两种朝向下完全相同**。**实现不得**按 `matchMedia` 或类名给键位写分支。

### 8.4 Tab 序列与"档位门"（**冻结**）

| 项 | 口径 | 理由 |
|---|---|---|
| 环内可点集合 | **只有 `--a5r-scale ≥ 0.72` 的卡（档位 1~3，即 5 张：焦点卡 + 左右各 2 张）**进 Tab 序列 ⇒ 动态设 `tabindex="0"` / `tabindex="-1"` | ① 9 张全进 Tab 序列 ⇒ 用户要按 9 次才穿过环；② 档位 4/5 已被前面盖住大半且模糊到 6px（§4.3.1），把不可读的东西放进焦点序列是**可及性问题**（不是命中问题，§4.6） |
| 焦点卡 | 永远 `tabindex="0"` | |
| 非焦点但档位 1~3 的卡 | `tabindex="0"`（可被 Tab 到达） | |
| 档位 4/5 的卡 | `tabindex="-1"` | 仍可**鼠标点击**（§4.6 命中区达标），只是不进键盘序列 |

### 10.4 CSS 变量（**冻结**）：谁是静态、谁是每帧写入

> 这一节是给实现的**接口契约**：分不清"谁写"就会写出互相打架的两套逻辑。

| 变量 | 写在哪 | 谁写 | 何时写 | 取值范围 |
|---|---|---|---|---|
| `--a5r-radius` | `.a5r-ring` | **静态**（样式表） | 不写 | `600px` |
| `--a5r-step` | `.a5r-ring` | **静态** | 不写 | `24deg` |
| `--a5r-slot` | `.a5r-ring` | **静态** | 不写 | `249.6px`（"一格"在**承轴**方向的屏幕位移）。**两种形态都是 249.6px**，差别只在轴：水平形态是横向、垂直形态是纵向（§11.3）。**不要**给它乘 `--a5r-vscale` |
| `--a5r-vscale` | `.a5r-ring` | **静态** | 不写 | `0.5`（水平形态的**起伏轴**压缩系数，§4.5）；`.a5r-ring--vertical` 下为 `0.35`（垂直形态的**起伏轴** = 横向，§11.3） |
| `--a5r-slot-focus` | `.a5r-ring` | 静态 | 不写 | `42%`（环心纵向，§4.5） |
| `--a5r-scale` | `.a5r-card` | **脚本，每帧** | 焦点更替 / 拖拽 / 惯性 / 吸附 | `1.00 / 0.85 / 0.72 / 0.61 / 0.58` |
| `--a5r-blur` | `.a5r-card` | **脚本，每帧** | 同上 | `0 / 2px / 4px / 6px / 6px` |
| `--a5r-opacity` | `.a5r-card` | **脚本，每帧** | 同上 | `1.00 / 0.72 / 0.44 / 0.28 / 0.28` |
| `--a5r-z` | `.a5r-card` | **脚本，每帧** | 同上 | `500 / 400 / 300 / 200 / 100` |
| `--a5r-dx` | `.a5r-card` | **脚本，每帧** | 同上（卡中心的屏幕水平偏移，取 §4.3 的 `d(k)`，**带符号**） | `0 / ±249.6 / ±460.7 / ±570.7 / ±654.6` |
| `--a5r-dy` | `.a5r-card` | **脚本，每帧** | 同上（卡中心的屏幕纵向偏移，取 §4.5 的 `y(k) − 454`） | `0 / −23 / −59 / −95 / −134` |
| `--a5r-lift` | `.a5r-card` | **脚本 / 状态类** | 悬停态写 `-4px`，否则 `0`（§6.1） | `0px` / `-4px` |
| `--a5r-ring-rescale` | `.a5r-card` | **脚本，每帧** | 同上（`= 1 / --a5r-scale`） | `1.00 / 1.176 / 1.389 / 1.639 / 1.724` |
| `--a5r-ring-pad` | `.a5r-card` | 静态 | 不写 | `var(--ring-offset)` = `2px` |

> **卡的定位方式（冻结，只有一种）**：`.a5r-card` 是 `position: absolute`，`left: 50%`、`top: var(--a5r-slot-focus)`，其**屏幕位置**全部由 `transform` 表达：
> `transform: translate(-50%, -50%) translate(var(--a5r-dx), calc(var(--a5r-dy) + var(--a5r-lift))) scale(var(--a5r-scale))`
> - `translate(-50%, -50%)` **必须最前**（先把卡片中心对齐到 `(50%, 42%)`，再串其他位移与缩放），否则缩放会把中心带偏。
> - `--a5r-dx` / `--a5r-dy` 由脚本每帧写；`--a5r-lift` 是**悬停微抬的唯一入口**（§6.1）。
> ⇒ **三条硬约束**：① **不要**用 `flex` / `gap` / `margin` 排 9 张卡（§4.3 的"必读的一条"已说明原因：`scale` 不改变占位，flex 排开会让"布局重叠"与"视觉重叠"混为一谈）；② **不要**把 `transform` 整串写成行内 `style.transform`（那样悬停的位移与进入的放大就会互相覆盖）；③ **所有位移与缩放都走 CSS 变量**，状态类只改变量值、不写 `transform`。

> **实现注意**：`--a5r-scale` 等 7 枚变量由脚本写入**行内样式**（`style.setProperty`）。**禁止**在样式表里给 `.a5r-card` 写 `--a5r-scale` 的默认值再让脚本去改 —— 行内变量天然盖过样式表，两处都写等于留下"看起来生效其实没生效"的死代码（旧 v1 页在 `:1451-1454` 的注释里踩过同类坑：行内 `transform` 盖掉样式表的 hover 规则）。

> 起因：产品侧（§11.5 的 `MenuView.vue`）随 PR **#95 拆两批**被撤回（见 `docs/RECORD.md` §5.8），
> 本批把它重新入 `main`；入 `main` 前**逐条实测**了正文没写清的三件事，落成下表。

| # | 项 | 正文怎么写的 | 实现 / 实测是什么 | 为什么 |
|---|---|---|---|---|
| **E-1** | **点击口径：非焦点卡先转到正中、不进入** | 正文 §7 的状态机（§7.1）与交互表只写**拖拽 / 惯性 / 吸附**，**没有**这一条；§6.1 的三类反馈也没有"点击"这一维 | `onCardClick`：`idx !== focus` ⇒ `snapTo(idx)`（**不导航**）；`idx === focus` ⇒ `enterWithFeedback(card)`（进项目）。**与排版稿 P1 逐条同源**（`pages/a5-menu-ring.html:523-529` 的 `wrap(Math.round(focusFloat)) !== i ? snapTo(i) : enterFocused()`），**零偏差** | 旋转木马上"点一张侧卡"的直觉是**把它转到面前**（先看，再进），不是"隔着 244px 的斜角直接进项目"。⇒ 一并解释了冒烟的写法：脚本必须点**焦点卡**才等价于"点一张项目卡进项目" |
| **E-2** | **`.is-focus` 与"可点"的关系：焦点卡在重叠区是命中赢家** | §5.3 只给 z 的档位值；§4.6 只给最小命中尺寸（≥44）；**没有**写"相邻卡重叠 88px 时谁接指针" | 真 Chromium 实测（1920×1080 口径的 1280×800 视口，`.a5r-card.is-focus` = 环序 1）：焦点卡 rect `(460, 366, 360×420)`，邻卡 rect `(731, 392, 306×357)` ⇒ **横向重叠 88px**；在焦点卡的**中心 / 左 25% / 左 10% / 左 2px / 右 90% / 上 25%** 六个点做 `document.elementFromPoint`，**六点全部落在 `is-focus` 那张卡上**（`ownerCard=0`）⇒ 重叠区不会把点击抢给邻卡。机制：`.a5r-card` 的 `z-index: var(--a5r-z)` 逐档 `500 / 400 / …`（§5.2 / §26.3），焦点卡恒在最上层 | 这条是**可点性**的机械证据（§7 之外、但决定"点得中点不中"）。冒烟里曾出现「邻卡子树 intercepts pointer events」——那是**开场旋转期间**取样撞上运动中的环，**不是**真实遮挡（见 E-3） |
| **E-3** | **`SPIN_MS` 是冒烟脚本必须等的量：等与不等，最终态逐字段相同** | 正文没有（开场旋转本身由附 D 的 D-4 引入） | ① 不等（`goto #/menu` 后立刻点）⇒ Playwright 报 `element is not stable` 并重试到 30s 超时（每帧 `applyRing()` 写 `--a5r-dx / --a5r-dy` ⇒ 每张卡都在动）；② 等 `SPIN_MS + 余量`（本批取 **`MENU_INTRO_MS = 2200`**，用在 3 处）⇒ 冒烟**全绿**（85 条 PASS）；③ **`reducedMotion: 'reduce'`（跳过开场）与正常播完的最终态读数逐字段相同**：焦点卡 rect 都是 `(460, 366, 360, 420)`、可见卡都是 9、`--a5r-ring-height` 都是 `618px` | 说明开场旋转**只影响那 1900ms**、不改变落位（`startIntro` 终点恒为环序 0）。⇒ 冒烟**没有再走**"给整条脚本开 reduced-motion"那条路：那会把同一份脚本后面 `ui-page-* / ui-station-*` 的过渡断言一起压成瞬时（§12 的 V-O 另在 8e 单点验过一次），属**扩大作用域**。**取"等"**——它只作用于目录页那三处，其余断言一字不动 |
| **E-4** | **产品侧"面板高度链"：环的上游高度不吃 `inset: 0`** | §10.3 / §26.1 的口径是**排版稿**的（`.a5r-ring` 相对 `.board__body`、恒高 1080）。**产品侧没有 1080 画布** ⇒ §26.1 头注已声明"产品不给 `--a5r-ring-height` 时靠祖先给像素值" | 产品的接链在 `web/src/styles/product.css` 的「目录页（A5）」一节：`.app-main__body > .ui-panel { height: 100% }` → `.ui-panel--ring > .ui-panel__body { flex: 1; min-height: 0; overflow: hidden; padding: 0 }` → `.a5r-stage-body { height: 100% }`。**实测（真 Chromium）**：`.ui-panel` **664** / `.ui-panel__body` **618** / `.a5r-stage-body` **618** / `.a5r-ring` **618** / `--a5r-ring-height` = **618px** / 可见卡 **9** | ⚠️ **链断掉时是静默塌陷**：环 / 轨道 / 9 张卡全是 `position: absolute` ⇒ 面板唯一在流子项高度为 0 ⇒ 面板塌到只剩 46px 头部、`--a5r-ring-height` 算成 `0px`（**0 是合法长度，`var()` 不会回退**）⇒ `.a5r-ring { height: 0; overflow: hidden }` 把 9 张卡整块裁掉：**页面空白、DOM 在、单测过、typecheck 过**。⇒ 产品侧**不得**把这三条当"多余样式"删掉；正文 §10.3 的 `inset: 0` 写法只适用于排版稿的 1080 画布 |

> **复核方式**：① 起 dev 服务、真 Chromium 进 `#/menu`，读上表 E-4 的五个高度与可见卡数（应 664 / 618 / 618 / 618 / 9）；② 在焦点卡中心与左缘 `elementFromPoint`，应恒为 `is-focus` 那张（E-2）；③ 目录页加载后**立刻**点焦点卡应报 `element is not stable`，等 2s 后再点应正常进项目（E-3）；④ 点一张**侧卡**应只把它转到正中、**不进项目**（E-1）。
